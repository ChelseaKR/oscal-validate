# Targets for docs/findings/. One line per document:
#   group<TAB>url<TAB>comma-separated URLs to hand this target with --resolve
#
# The sample is purposive, not random. It is every OSCAL JSON instance NIST
# publishes as an example, NIST's own control catalogs and baselines, the
# FedRAMP baselines and templates as they survive today, and a spread of
# third-party publishers. See docs/findings/ for what that supports and what it
# does not.
#
# The third column is the target's effective data model: the documents it
# imports, directly or transitively. Those URLs are fetched on the same terms as
# a target and are NOT surveyed, so a document that appears only there is never
# counted in the denominator. Fifteen appear here; ten of them are also targets
# in their own right and five are not. Every entry was derived from an
# IMPORT_NOT_SUPPLIED finding in the 2026-08-14 run and walked to a fixed point;
# the three cases where matching a file name to a published copy is a judgement
# rather than an identity are named under "Method" in
# docs/findings/2026-08-15-imports-supplied-survey.md.
#
# Fifteen targets are deliberately left incomplete because nothing public can
# complete them: nine import a profile whose only rlink is a release ZIP, five
# import a relative path that does not exist in the repository that publishes
# them, and one imports a back-matter UUID it never declares. Those are findings,
# not omissions, and they are written up under Finding 3.
#
